## Stack

React 19, TypeScript, TanStack Start (server rendering + client hydration) with TanStack Router (file-based, `src/routes/`) and TanStack Query, Tailwind CSS v4, shadcn/ui (`src/components/ui/`), react-hook-form + Zod, sonner toasts, Playwright. ESLint: typescript-eslint, react, react-hooks (incl. React Compiler rules), jsx-a11y.

## Config

- `VITE_API_BASE_URL` (default `http://localhost:9095`, read in `src/lib/config.ts`). It is baked in at build time.
- Import alias `@/` → `src/` (from `tsconfig.json`, through `vite-tsconfig-paths`).
- `src/routeTree.gen.ts` is generated by the router plugin (`bun run dev` or `bun run build`). Do not edit it. After you add a route file, run `bun run build` once before `bun run typecheck`, or `tsc` fails on the new path (`make check` builds first).

## API layer

- **Endpoints:** every backend path is in `API` in `src/lib/api-endpoints.ts`. URL builders live there too (`buildItemsListUrl(params)` turns `name` into `name__ilike=%term%`, with `%` and `_` escaped).
- **Client:** `api.get/post/put/patch/delete` from `src/lib/api-client.ts`. It adds `Authorization: Bearer <token>` and throws `ApiError`.
- **Queries and mutations:** one hook per operation in `src/hooks/use<Feature>.ts`. Keys come from `src/lib/query-keys.ts` (`items.all`, `items.list(params)`). Mutations invalidate the feature's `all` key.

```tsx
export function useItems(params?: ItemsParams) {
  return useQuery({
    queryKey: queryKeys.items.list(params),
    queryFn: () => api.get<ItemsResponse>(buildItemsListUrl(params)),
    placeholderData: keepPreviousData,
  })
}
```

## Errors

The backend sends `{detail, error_code}` (see `../backend/AGENTS.md`). `ApiError` has:

- `status`, `message` (the backend `detail`), `code` (the backend `error_code`, or `network_error` / `invalid_error_body`).
- `fields` only for a 422 with a list `detail`: `{ [field]: [msg, ...] }`, and `message` = `"field: msg; ..."`.
- A 401 sent with a token, or a 403 `Not authenticated`, clears the token and gives the message `Your session has expired. Please sign in again.` Pages in `_authed/` then go to `/login?redirect=...`. A 401 without a token (wrong password) keeps the backend message.

Show errors with `toastApiError(error, 'Could not save item')` from `src/lib/error-handler.ts` (one toast: title + reason).

## Auth and pages

- Token in `localStorage` (`src/lib/auth.ts`); state in `AuthContext` (`useAuth()`).
- **Protected pages go in `src/routes/_authed/`.** The layout is client-only (`ssr: false`) and redirects after hydration. Do not add auth redirects in `beforeLoad`: the server cannot read `localStorage`.
- Server-rendered forms stay disabled until `useHydrated()` is true. Auth forms use `noValidate` so the Zod messages show.
- `/login?redirect=` accepts only in-app paths.

## Forms and UI

- Zod schema in `features/<feature>/<entity>-schemas.ts` (e.g. `features/items/item-schemas.ts`) + `useForm({ resolver: zodResolver(schema) })`.
- Use `FormField`/`FormItem`/`FormLabel`/`FormControl` from `components/ui/form.tsx`: `FormControl` puts the id and aria attributes on its one child, so the label names the input (tests use `getByLabel`).
- `Button` has no `asChild`. To style a link as a button use `buttonVariants()`. Add shadcn components to `components/ui/` only.

## Testing (end-to-end only)

No unit tests, no Vitest/Jest/Testing Library, no mocks, no `page.route()` or other network interception. Playwright runs against the real Vite server, the real backend and a real Postgres. `bun run test:e2e` starts and stops all three (ports 55432 / 59095 / 53000).

- Requirements: Docker, uv, bun, and `bunx playwright install --with-deps chromium` once.
- New spec: `e2e/<feature>.spec.ts`, starting with `import { test, expect } from './fixtures'`. Seed data only through the real API; put helpers for a new resource in `e2e/fixtures.ts`.
- Fixtures: `api`, `user`, `authedPage`, `loginAs`. Helpers: `registerUser`, `loginUser`, `createItem(s)`, `listItems`, `uniqueEmail` (uses `@example.com`), `PASSWORD`, ...
- `e2e/guards.spec.ts` fails when a page is never opened (`page.goto` / `toHaveURL`), an `API` endpoint is never used by a spec or fixture, or a mock library is in `package.json`. ESLint fails on network stubbing (incl. CDP sessions), `waitForTimeout`, `test.skip/only/fixme`, a `retries` override and imports of `@playwright/test` outside `fixtures.ts`.
- Failed test: trace and screenshot in `test-results/<test>/`; open with `bunx playwright show-trace <trace.zip>`.

Full guide: `../.claude/skills/project-standards/references/e2e-testing.md`.
